# 股神乐开发和服务宪章

> 版本 v1.0 · 2026-09-23 · 与 Sam 共同确认
> 本文件是股神乐长期开发与服务的最高依据，版本化保存，修订需记录在文末"修订记"。

---

## 总纲（宪法级原则，任何方向不得违背）

1. **轻**：股神乐不能背负太重。优先确定性、本地、低维护的方案；新数据源先研究、再商量，不直接接入。
2. **行为纠偏，而非预测**：谷峰律动的核心价值是拦追高、拦割肉，不是水晶球。任何算法升级不得把"预测"卖成"承诺"。
3. **可解释优先于黑箱**：用户要看得懂的道理。不做机器学习黑箱。
4. **用户数据归用户**：画像、记录、操作记忆可看、可改、可删；家人可见范围由用户决定。
5. **家庭陪伴**：个人与家庭的投资陪伴，快乐炒股，轻松投资；不赌不堵，不气不弃。
6. **纪律**：一次只动一个参数；效果用复盘台账说话，没有台账的调参是玄学。

## 方向一：谷峰律动模型精进

**愿景**：用真实使用数据与复盘台账，把律动打磨成真正有价值的核心算法。

**原则**
- "数据训练"指复盘数据驱动的**确定性调参**，不是 ML 黑箱（总纲第 3 条）。
- 先有台账再调参：/api/accuracy 每日收盘自动跑、结果持久化存档（2026-09-23 已立项的优化计划继续有效）。
- 超卖端、信号分级（注意→警告→强烈）、市况开关、量能增强、操作记忆个性化，按既定优先级逐个来。

**约束**：阈值保持整数，拒绝过拟合；牛 / 熊 / 震荡分段验证。

## 方向二：用户画像与偏好分析（记忆页）

**愿景**：根据用户的真实操作、记录和分享，形成精准的用户偏好分析与画像呈现，陪用户一起成长；经用户同意，家人也能看到。

**原则**
- 画像来自真实行为（操作—情绪—结果样本），不贴标签、不臆测。
- **用户可认可、可修订**：画像的每一条结论都要能被用户点"对 / 不对"修正；修了就记下来，下次更准。
- 可见范围用户说了算：默认仅自己，可选对家人开放。
- 长期目标：卖飞率 / 买高率 / 专属胜率等个性化复盘，比通用信号值钱。

**约束**：样本量不够时不硬给结论，宁可说"样本还不够，再记几笔"。

## 方向三：股票覆盖扩充

**愿景**：尽可能多地覆盖股票，但不牺牲访问速度。

**原则**
- 当前约 170 只本地名单是单一数据源（`src/lib/stockList.ts`），扩充沿这条路走：本地索引 + 按需拉行情。
- 扩充先做"广度"（更多代码、更准的中文名），再做"深度"（更多实时字段）。

**约束与成本**
- 全美股（约 6000+ 只）需要稳定名单源（如 Nasdaq screener 类接口），中文译名需人工审计——这是持续维护成本。
- 速度红线：搜索、筛选、自选加载不得变慢；批量实时行情不开，沿用"只拉自选"的策略。
- 需要升级支持服务（数据预算、缓存、配额）时，单独讨论，不先斩后奏。

## 方向四：中英双语（尽快）

**愿景**：提供英文服务，同时帮助中文用户学习股市英语（中英对照本身就是特色）。

**原则**
- 越早做越便宜：UI 字符串现在不到爆炸点，i18n 基建应优先排期。
- 双语不只是翻译：诊断大白话、股票名、教育内容都要有"股市英语"的对照味道。
- 默认语言跟随用户选择，中英可一键切换。

**约束**：选型倾向轻量（自研词典或最小依赖），不引入重型 i18n 框架背负担。下一步：先出 i18n 基建方案再动手。

## 方向五：投资教育体系

**愿景**：一步步形成我们自己的、有温度、有效用的炒股和投资理念、逻辑与打法。

**原则**
- 从律动实践中长出来：每一条理念都要有"为什么"和"什么时候不灵"。
- 少而精：先做 10 篇经得起时间考验的，不做 100 篇水文。
- 与"用法"页衔接：教育内容是用法指南的加深版。

**约束**：内容生产是持续成本，节奏服从质量；不碰"保证收益"类表述（总纲第 2 条）。

## 方向六：支付（打赏制 vs 会员制，对比后决策）

**现状**：待决策。先做全方位对比，再由 Sam 拍板。

**对比维度**
| 维度 | 打赏制 | 会员制 |
|---|---|---|
| 收入 | 随缘、波动大 | 稳定、可预期 |
| 技术成本 | 轻（一次性接入） | 重（权益、续费、到期、退款） |
| 运营成本 | 几乎为零 | 客服、权益纠纷、续费提醒 |
| 合规 | 简单 | 发票、税务、自动续费规范 |
| 用户心理 | 无压力、好感 | 付费即有期待，交付压力大 |
| 与"轻"原则契合度 | 高 | 低 |

**倾向**：先打赏制跑通心意与支付链路，会员制等内容/服务厚到值得付费时再议。

## 方向七：App 化（iOS / Android 上架）

**愿景**：进苹果 / 谷歌商店，供下载使用。

**路径**：PWA 先行（零商店成本，验证"装到桌面"的真实需求）→ 封装（如 Capacitor）→ 上架。

**约束与成本**
- Apple 开发者年费 $99/年 + 审核；Google $25 一次性 + 审核。
- 上架后：双端更新、审核规则、崩溃率都是持续负担——这是"变重"的决定，需单独评估时机。
- 在 PWA 数据出来之前，不启动上架流程。

## 方向八：主播 / 大 V 读取与评价，以及理念契合的优化

**愿景**：读取和评价主播、大 V 等有价值的内容，只做与我们理念契合的部分。

**原则**
- 先立"理念契合"标准，再谈接入谁；不契合的不做。
- 公开评价涉及名誉权与合规风险：只做信息聚合与理念维度呈现，不做人身评价；措辞走法务口径（见页脚"版权与法律"）。

**约束**：数据源维护重、法律风险高，排序后置；可先以"有温度的内容聚合"轻方案试水。

## 路线图建议（优先级排序）

- **P0（尽快）**：方向四双语 —— i18n 基建越早越便宜，先出方案。
- **P1**：方向一律动精进（复盘台账先行，与既有优化计划衔接）、方向三覆盖扩充（轻量先行：名单先扩到 ~1000 只本地 + 按需行情）。
- **P2**：方向二用户画像（等操作记忆样本积累）、方向五投资教育（少而精起步）。
- **P3（决策/验证后）**：方向六支付（先出对比结论）、方向七 App 化（PWA 数据先行）、方向八大 V 评价（法律与维护成本最高，后置）。
